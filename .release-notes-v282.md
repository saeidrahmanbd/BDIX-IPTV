# 📺 Playlist Studio v2.8.2 — Playback Stability

![Playlist Studio v2.8.2](https://raw.githubusercontent.com/saeidrahmanbd/BDIX-IPTV/main/assets/Playlist-Studio-screenshot.png)

**Released:** September 13, 2026  
**Platform:** Windows  
**Format:** Single-file portable application

Playlist Studio v2.8.2 focuses on **playback stability and recovery**. The IPTV player now runs separately from the main playlist editor, so a native playback failure is isolated instead of closing the entire application.

> **Key improvement:** Playback failures are now contained within the player process, allowing the playlist editor to remain usable.

## ✨ What's new

- ▶️ **Isolated playback process** — the VLC player runs separately from the main editor.
- 🔄 **Fresh process on channel switching** — each channel starts with a clean playback state instead of reusing the previous channel's TLS or decoder state.
- ⚡ **Smarter channel switching** — rapid channel requests are consolidated so only the latest request is processed.
- 🛡️ **Bounded recovery** — stalled playback processes are terminated after a bounded timeout so channel switching can continue.
- 🔧 **Playback recovery** — stopped or unresponsive playback shows a recovery message with **Retry** or channel-selection options.
- 🔊 **Settings preserved** — volume, mute, and view settings are retained across channel changes.

## 🎯 Why this release matters

Windows crash reports identified access violations in VLC 3.0.23's HTTPS plugin, `libgnutls_plugin.dll`. In version 2.8.1, such native playback failures could close the entire playlist editor.

Version 2.8.2 changes the playback architecture so these failures are isolated to the playback process rather than taking down the main application.

## ⚠️ Important notes

The bundled VLC version is **unchanged**. This release does not claim to repair VLC or the underlying native library.

A failed stream may still require **Retry** or selection of another stream URL. Because each channel switch starts a new player process, a brief startup delay can occur.

## 🧪 Validation & testing

The following were successfully verified:

- Native playback
- 15 queued channel switches
- Deliberate playback-process termination with editor survival
- Playback recovery
- Stop
- Pause and resume
- Asynchronous playlist drops
- Repeated fullscreen resizing with volume controls
- Packaged portable EXE startup
- Playlist import
- HTTP test-stream playback

Fullscreen geometry, restoration behavior, and control visibility were also verified separately. Desktop-wide hit testing of fullscreen buttons was partially obscured during one test by the Windows Date and Time panel.
