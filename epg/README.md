# EPG setup, mapping, and publication status

## Current pipeline

The shared XMLTV guide is generated by the repository's **IPTV Playlist Update** maintenance workflow. The mapping/coverage scripts currently audit the three core playlists in the automated EPG pipeline:

- `BDIX-Playlist.m3u`
- `IPTV-Playlist.m3u`
- `International-Playlist.m3u`

The generator writes `epg/epg.xml`. The three core playlist headers should reference this published location:

`https://raw.githubusercontent.com/saeidrahmanbd/BDIX-IPTV/main/epg/epg.xml`

The fourth repository playlist, `BD.IN-Playlist.m3u`, is not currently included in the EPG generator or these coverage reports; do not infer EPG coverage for it from the shared-guide metrics. Coverage reports are written to `reports/epg-coverage.md` and `reports/epg-three-playlist-audit.md` (the latter filename is retained for compatibility and measures the three core playlists). The overall totals in `epg-coverage.md` aggregate active unique IDs across those three core playlists; use the per-playlist row in `epg-three-playlist-audit.md` for `IPTV-Playlist.m3u`-only coverage. The XMLTV guide itself is shared. Identity-to-source mappings live in `reports/epg-india-channel-mapping.csv`.

## Coverage caveat

A playlist header pointing at the shared XMLTV file does not guarantee that every channel has programme listings. Domestic Bangladesh coverage remains limited unless an exact, schedule-backed source mapping is verified. Do not guess EPG IDs or publish fabricated schedules to increase the coverage percentage.

## Redistribution status

**Rights to publicly redistribute programme-guide data have not yet been confirmed for every source.** A source being publicly reachable does not itself grant redistribution permission. The coverage reports measure technical mapping and schedule availability; they are not licensing approval or a statement that every item is cleared for public redistribution. Review applicable source terms before relying on or redistributing the generated guide.

## Sources

The synchronized source pool includes India, UK and US feeds plus regional feeds selected to match channels present in the playlists: UAE, Australia, Canada, Switzerland, Czech Republic, Germany, Dominican Republic, Spain, France, Greece, Hong Kong, Hungary, Italy, Malaysia, Mexico, Netherlands, Poland, Romania, Saudi Arabia and Turkey, plus dedicated beIN and Brazilian feeds. The United States feed [`https://iptv-epg.org/files/epg-us.xml.gz`](https://iptv-epg.org/files/epg-us.xml.gz) supplements the epgshare US2 feed. The coverage analyser and XMLTV generator use the same source list; a configuration check fails if the lists drift. Dedicated UK diaspora feed IDs are explicit mappings and are not treated as evidence for unrelated domestic services. Most remote sources are XMLTV feeds. The official HUM TV Pakistan schedule is HTML and uses a dedicated parser that extracts only explicit title/time entries. Compressed URLs are detected and decompressed before XML parsing. Source availability and channel counts do not guarantee a valid channel schedule; the coverage report checks eligible non-empty multilingual programme titles under the repository's language-priority policy (English first, then Bengali, then other valid languages) and verifies actual overlap with the published XMLTV.

Two dedicated EPG.PW XMLTV feeds are explicitly mapped for the UK diaspora services NTV Europe (`epgpw:9374`) and Channel S UK (`epgpw:12504`); the source feed's single channel ID is normalized to a stable internal source ID before mapping. ATN Bangla UK retains its verified `6753` mapping. These individual feeds do not represent a general domestic Bangladesh guide. The source list also includes supplemental Samsung TV Plus India and US guides (`https://i.mjh.nz/SamsungTVPlus/in.xml` and `https://i.mjh.nz/SamsungTVPlus/us.xml`) plus targeted DistroTV, Plex, and Rakuten TV XMLTV feeds to improve FAST/streaming-channel coverage. Bangladesh-group services are matched only using an exact playlist `tvg-id` or an explicitly configured alias; name-only fuzzy matching remains disabled for those services. The EPG catalogue identifies South Station as `SouthStation.in@HD`; the coverage script accepts that mapping only when a configured XMLTV source contains the exact ID, and the report separately checks for current/future programmes.

## Optional M3U4U supplemental feed

The personalized M3U4U XML and XMLTV (GZ) endpoints are alternate formats of the same guide; configure only the compressed endpoint. The maintenance scripts support it through the GitHub Actions repository secret **`M3U4U_XMLTV_URL`**. Store an **HTTPS** M3U4U `/epg/` or `/xml/` endpoint in that secret; never paste the personalized URL into source code, workflow YAML, playlist files, or reports.

To enable it, open the repository's **Settings → Secrets and variables → Actions → New repository secret**, set the name to `M3U4U_XMLTV_URL`, and use the HTTPS version of the supplied compressed endpoint as its value. The scripts validate the host/path before using it, and mask the endpoint in generated mapping and source-status reports. If the secret is absent or invalid, maintenance continues with the existing public sources.

M3U4U schedules are considered alongside existing feeds; they do not replace them. Matching stays subject to exact channel IDs/explicit aliases for Bangladesh services and valid non-empty multilingual title/time-window checks. The title preference is English, then Bengali, then other valid languages. The sample feed includes titles in Hindi, Telugu, Hungarian, Dutch, and other languages. These remain eligible when the programme interval and title are valid; when multiple title variants describe the same programme, the generator prefers English, then Bengali, then another valid language. Automated retrieval and public redistribution rights for programme data still need to be confirmed before public schedule publication.

## Mapping safeguards

- Keep each playlist's `tvg-id` unchanged. For a known channel represented by different IDs in separate playlists, add a narrow, documented alias in `scripts/epg_coverage.py`; do not merge identities based on a loose name match.
- Candidate aliases are accepted only when one of the configured XMLTV sources contains the exact candidate ID. Catalogue IDs establish channel identity, not that a schedule is currently available.
- Indian Bangla channels retain a single primary EPG source ID to reduce the risk of mixing schedules from different feeds.
- `HumTV.pk` uses only explicitly titled/time-labelled entries from the official domestic [HUM TV schedule](https://hum.tv/schedule/). The source page's 24-hour grid is hourly, so the adapter assigns one-hour slots; it does not fabricate titles for unlabeled slots and does not use HUM World/EU/MENA schedules for the Pakistan-local channel ID.
- Do not infer Bangladesh channel schedules from similarly named Indian channels. Add local mappings only after confirming a genuine Bangladesh listing source.
- Backup, Test, Not Playing, New Backup, and New Channels groups are excluded from active mapping coverage.
- Mapping coverage is not stream-health coverage. `MAPPED` means at least one configured source has current/future programme data; it does not guarantee that the live stream works.

## Programme-data permissions

**Automated retrieval and public redistribution rights for the configured programme-data sources have not been established.** Public accessibility of a feed, an open-source generator licence, and catalogue identity evidence do not by themselves grant permission to republish programme schedules. Obtain provider terms or written permission that covers automated retrieval and public XMLTV redistribution, or switch to a properly licensed source before treating public publication as approved. Do not mark any source policy approval fields true without supporting evidence.

## RTV Bangladesh

RTV (`RTV.bd`) is not a configured source: automated retrieval permission has not been obtained from RTV, and its site's robots.txt appeared to disallow automated access. The adapter code remains in `scripts/official_epg_sources.py` but is not used. Do not re-enable it without written permission.
